# 企画・技術設計書：コンビニ経営シミュレーション（仮称「まちかどマート」）

> 「ザ・コンビニ」の遊び心地（街に出店して陣取り、店がにぎわう様子を眺めながら発注・経営する）を参考にした**オリジナル作品**。名称・キャラクター・画像は流用しない。
> 現行の「カフェ経営アカデミー」で作ったレッスン・決算書の仕組みは引き継ぐ。

---

## 1. コンセプト

**「街を眺めながら、数字で勝つ」**
ドット絵の街でお客さんが歩き、店に入り、レジに並ぶ。その裏で動いているのは、立地・品揃え・発注・人員・資金の本物の経営ロジック。遊ぶうちに、MBA入門レベルの経営知識（商圏分析、ABC分析、廃棄と機会損失、人時生産性、ドミナント戦略、財務3表、投資回収）が身につく。

- 対象：経営を学びたい社会人・研修の受講者（中級／MBA入門）
- 端末：PCブラウザ＋スマホ（縦画面）両対応
- 1プレイ：1ステージ 20〜40分、全キャンペーン 5〜8時間

## 2. コアループ

```
 ┌──────────────── 1日（実時間 約2〜3分 / 1倍速）────────────────┐
 │ 朝：発注確定・シフト確認 → 日中：客が来店、売れる・欠品・廃棄 →   │
 │ 夜：日報（POS）とメンターの一言                                  │
 └──────────────────────────────────────────────────────────┘
        ↓ 7日ごと                         ↓ 月末
   週報：ABC分析・天気と売上           月次決算：P/L・B/S・C/F
                                       ＋ レッスン（その月の出来事と連動）
        ↓ 資金がたまったら
   新規出店（物件選び＝立地分析）→ 店舗が増える → 競合チェーンとの陣取り
```

- 一時停止・1倍・3倍・10倍速。発注締め／決算／イベント発生時は自動で一時停止
- 一時停止中は何でも操作可能（スマホでじっくり考えられるように）

## 3. ゲームシステム

### 3.1 街マップ
- タイル型マップ（例 64×48 マス、1マス=16px）。区画の種類：住宅街・オフィス・駅・学校・大学・幹線道路・郊外・観光地
- 各区画が**時間帯別の人口**（昼間人口／夜間人口）と**客層**（学生・会社員・主婦/主夫・高齢者・観光客）を持つ
- **空き物件**：家賃・広さ（棚の数）・駐車場の有無・前を通る人の数が異なる
- 出店画面で**商圏**（徒歩5分圏）を地図上に色付けして表示 → 人口・客層・競合店を確認して判断（＝立地・商圏分析）

### 3.2 店舗
- 棚の数は物件で決まる。棚ごとにカテゴリを割り当て（**棚割り**）
- カテゴリ（約10種）：おにぎり・弁当／パン／ホットスナック／飲料／アイス／酒／菓子／日用品／雑誌／たばこ
  - 各カテゴリの特徴：原価率、消費期限（日配品は1日、アイスは長い）、時間帯の売れ方、天気・気温への反応、客層ごとの好み
- 設備投資：ATM・コーヒーマシン・イートイン・駐車場拡張など（投資回収を学ぶ）

### 3.3 発注と在庫
- 毎朝、カテゴリごとに発注（翌朝入荷＝リードタイム1日）
- **自動発注の推奨値**（過去7日平均×天気予報補正）を表示し、プレイヤーが上書き → 予測が当たったか外れたかを日報で確認
- 期限切れは廃棄、品切れは**機会損失**として日報に表示（ゲームが計算した「本当は売れた数」を見せる＝現実では見えない数字を見せる学び）

### 3.4 お客さん
- **実際の売上は統計モデルで計算し、画面のお客さんはそれを元にした「見せるための代表者」**（設計判断は 5.3 参照）
- 来店数 = 商圏の時間帯人口 × 客層ごとの来店率 × 店の魅力度（品揃え・評判・待ち時間）÷ 競合との分け合い
- レジ待ちが長いと離脱し、評判が下がる

### 3.5 スタッフ
- 時間帯ごとのシフト（朝・昼・夕・深夜）。人数が足りないとレジ待ちが増え、品出しが遅れる
- 時給・深夜割増・最低賃金の改定イベント
- 指標：**人時売上高**（売上 ÷ 総労働時間）

### 3.6 競合チェーン（AI）
- 2〜3社。それぞれ性格が違う：「駅前・都心を狙う大手」「郊外で安売りする」「高品質で少数精鋭」
- 空き物件を取り合う。同じ商圏に店が増えるほど客を分け合う
- 自社の店を密集させると物流費が下がり、知名度が上がる（**ドミナント戦略**）が、自社の店どうしで客を奪い合う問題も

### 3.7 お金
- 月次で P/L・B/S・C/F（カフェ版の仕組みを拡張）
- 銀行借入（金利・返済期間・融資枠が業績で変わる）、出店費用の減価償却
- 現金が尽きたら倒産（黒字倒産もありうる）

### 3.8 イベント
- 天気（毎日）：雨・猛暑・寒波 → カテゴリ別の売れ方が変わる
- 季節・暦：花見・夏祭り・お盆・クリスマス・恵方巻
- 経済：原材料高騰、最低賃金改定、増税（価格転嫁の判断）
- 街の変化：駅前再開発、大学の開校、工場の閉鎖（商圏が変わる）

## 4. 学習のしかけ

| 学ぶこと | ゲームでの体験 | 確認する画面 |
|---|---|---|
| 立地・商圏分析 | 物件選び | 商圏マップ、昼間人口・夜間人口 |
| ABC分析・パレートの法則 | 棚割りの見直し | 週報（売上構成のグラフ） |
| 需要予測・廃棄と機会損失 | 毎朝の発注 | 日報（廃棄数・欠品数） |
| 粗利ミックス | 原価率の違うカテゴリの配分 | カテゴリ別の粗利 |
| 人時生産性 | シフト作成 | 人時売上高 |
| 損益分岐点 | 新店の黒字化 | 店舗別P/L |
| 財務3表・資金繰り | 借入して出店 | 月次決算 |
| 投資回収・NPV | 設備投資・出店 | 投資シミュレーター |
| ドミナント戦略・競争戦略 | 競合との陣取り | 地域シェア |
| 外部環境（PEST） | 再開発・制度変更 | ニュース |

- **メンター**：「新人店長」から「チェーン社長」になるまで付き添うキャラクター。数字の変化を見て一言アドバイス
- **レッスン**：ステージ中のイベントで解禁。現在の12レッスンを再編・拡張（20本程度）
- **キャンペーン（ステージ制）**で段階的に機能が開放される：
  1. 1号店（発注と廃棄だけ）
  2. 棚割りと天気
  3. シフトと人件費
  4. 2号店の出店（立地分析・借入）
  5. 競合チェーン登場
  6. 街の再開発・ドミナント戦略
  7. フリープレイ（全機能、スコアアタック）

## 5. 技術設計

### 5.1 技術スタック
| 用途 | 採用 | 理由 |
|---|---|---|
| 言語 | **TypeScript** | 型でシミュレーションのバグを防げる。Next.js/TSの経験が活きる |
| ゲーム描画 | **Phaser 3** | 2Dのタイルマップ・スプライト・カメラ・タッチ操作が揃っている。Webで実績が多い |
| 経営画面のUI | **Preact**（React互換の軽量版）＋ CSS | 表・グラフ・フォームはHTMLのほうが作りやすく、スマホのスクロールや文字の読みやすさも良い。Reactの書き方そのまま |
| グラフ | 自作SVG（または uPlot） | 軽さ優先 |
| ビルド | **Vite** | 高速。GitHub Pagesの配信先パス（base）の設定も簡単 |
| テスト | **Vitest** | 経営ロジックの数値を自動テスト |
| マップ作成 | **Tiled**（無料のマップエディタ） | JSONで書き出してPhaserでそのまま読める |
| 素材 | Kenney（CC0）など＋必要に応じて自作 | 商用でも使える。ライセンス一覧を `CREDITS.md` に記録 |
| 公開 | **GitHub Actions → GitHub Pages** | pushすると自動でビルドして公開 |

**GitHub Pagesで問題ない理由**：すべてブラウザ内で完結する静的サイトなので。セーブはブラウザ内（IndexedDB）に保存する。ランキングやクラウドセーブが欲しくなったら、Supabaseなどを後から追加する（設計上の差し込み口だけ用意しておく）。

### 5.2 アーキテクチャ（3層に分ける）

```
┌──────────────────────────────────────────────┐
│ UI層（Preact）  発注・棚割り・決算書・レッスン      │ ← スマホではボトムシート
├──────────────────────────────────────────────┤
│ 描画層（Phaser）  街マップ・お客さん・店内          │ ← シミュレーションの状態を「読むだけ」
├──────────────────────────────────────────────┤
│ シミュレーション層（純TypeScript）                │ ← 描画にもブラウザにも依存しない
│  時計・需要・在庫・人員・競合AI・会計・イベント     │   Vitestでテスト、Node上でも動く
└──────────────────────────────────────────────┘
       ↑ コマンド（発注する、出店する…）  ↓ 状態とイベント通知
```

- UIと描画層は**コマンド**でしかシミュレーションを変更できない → リプレイ・テスト・セーブが簡単
- シミュレーションは**決まった刻み（ゲーム内15分）**で進む。倍速は1フレームあたりの刻み数を増やすだけ
- 乱数は**シード固定**（同じシード＋同じ操作 → 同じ結果）。バランス調整の自動検証に使う

### 5.3 お客さんの計算方式（重要な設計判断）
- **売上は統計モデルで計算**（時間帯×客層×カテゴリの期待値＋ばらつき）
- **画面の歩行者はその結果を表示しているだけ**（1人が実際の客 N人分を代表）
- 理由：①スマホでも重くならない（画面外の店や10倍速でも計算量が一定） ②数値テストができる ③お客さんの歩き方の都合で売上が変わるバグが起きない

### 5.4 スマホ対応
- 縦画面：上半分に街マップ（ピンチで拡大縮小・ドラッグで移動）、下半分に操作パネル（ボトムシートで引き上げると全画面）
- 横画面・PC：左に街マップ、右にサイドパネル
- タップしやすさ（ボタンは最低44px）、文字は最低14px
- 描画のドット感を保つ（`pixelArt: true`、整数倍の拡大）
- 性能目標：ミドルクラスのスマホで 60fps、表示中の歩行者は最大150人程度

### 5.5 データ駆動
商品カテゴリ・物件・イベント・レッスン・ステージは **JSON/TSのデータファイル** にまとめる → コードを触らずにバランス調整やレッスン追加ができる（研修ごとのカスタマイズも可能）。

### 5.6 ディレクトリ構成（案）
```
src/
  sim/        シミュレーション（clock, demand, inventory, staff, rival-ai, accounting, events）
  data/       カテゴリ・物件・イベント・レッスン・ステージ定義
  game/       Phaserのシーン（Boot, Town, StoreInterior）とスプライト
  ui/         Preactの画面（発注、棚割り、日報、決算、レッスン、出店）
  save/       IndexedDBへの保存・読み込み
  main.ts
public/assets/  タイル・スプライト・効果音
tests/          シミュレーションの数値テスト・バランス自動検証
.github/workflows/deploy.yml
```

### 5.7 セーブ
- 1日の終わりに自動セーブ（IndexedDB）、手動スロット3つ
- セーブデータにバージョン番号を持たせ、アップデート後も古いデータを読める（マイグレーション）

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| ドット絵素材の統一感が出ない | 1つの素材セット（Kenneyなど）を軸にする。足りない部分だけ自作・生成し、色数を揃える |
| スマホで情報が多すぎる | ステージ制で機能を段階的に開放。数値は「要約→詳細」の2段構え |
| 数値バランスが崩れる | シミュレーション層を独立させ、自動プレイで戦略ごとの成績をテスト |
| 作る量が膨らむ | M1の縦切りで中核の手触りを先に確定。M4以降は優先度で取捨選択 |
| 元ネタとの類似 | 名称・キャラ・画面デザインはオリジナル。参考にするのは遊びの仕組みだけ |
